# hc-845 Video model selection

The Desktop video picker defaults to Seedance 2.0 Mini, saves apex.generation_video_model through the active runtime config API before acknowledging a change, and migrates a previously saved renderer-only choice like the image picker. Fresh seeds and upgrade reconciliation supply the same missing default without overwriting explicit preferences. Image and video settings remain independent.

The platform video plugin reads the preference on every call. Saved choices win over LLM arguments; absent Desktop preferences keep hosted legacy behavior. Invalid preferences fail before generation. The companion ApexNodes change also aligns the video catalog and unset paid-provider default to Mini; the existing paid-provider switch remains OFF until explicitly authorized. Public free Agnes endpoints keep their provider and pricing.

Outlets: renderer picker/default/legacy local selection, config save failure, fresh seed, upgrade reconciliation, current profile tool execution, curated model catalog and hosted/public legacy compatibility. Mac and Windows share the code; this source PR does not publish an installer or enable a provider.

## hc-948 bundled plugin binding

Until hc-948 the sentence above held only for the hermes-cloud copy of the video plugin. The Desktop runs this repo's `plugins/apexnodes-video-tools`, which never read `apex.generation_video_model`, so every Desktop video call went out without `model` and reached the Agnes leg (2026-10-18 review: three Agnes HTTP 503s). `_desktop_video_model()` now mirrors the image plugin's `_desktop_image_model()`. It runs on every call, on both the gateway and legacy paths: a saved choice wins over the LLM's `model` argument, an absent preference keeps the platform default, and a malformed or unknown value fails with a "当前视频模型设置" error before any request. The paired apex-nodes PR (same ticket) makes Seedance 2.0 Mini via chinaapi the platform default for calls without `model`.

## Source conversation model and input border

The single video conversation composer has a visible theme border and focus highlight. Its footer offers the same configured, product-filtered text model catalog as chat, plus Default (Agent settings). This chooses the model that answers source questions, independently of the image/video generation settings. The choice is local to the current analysis view and resets when its account, connection, profile or source ownership scope changes. Picking a row makes no model call and does not change the main chat model. During an answer the selector is disabled.

An explicit selection is passed as a provider/model pair, together with the active profile, to llm.oneshot task=source_question. The gateway forwards the pair to run_oneshot and the existing auxiliary client; existing credential resolution, retry/fallback policy and relay billing still apply. Default omits the pair and retains the configured task behavior. Partial/empty pairs fail before the model boundary. Both source-question action consumers use the active profile; document questions retain their existing UI and default routing. Other one-shot clients omit the new optional fields and keep the existing session/task behavior. No unrelated chat history is attached; citation validation and revision/owner checks remain mandatory.

Outlets checked: video form (one textarea, one send button), both source-question action callers, active-profile catalog cache/allowlist, question helper, gateway contract/generated TS and OpenRPC, gateway handler, shared one-shot model boundary, legacy one-shot callers and native saved answer/reopen/citation path. Existing summary/deep-analysis operations keep their own model policy.

## hc-1046 the assistant picks the generation model; the server serves the catalog

The ApexNodes server now keeps one media model catalog (its `app/services/media_model_catalog.py`): every image and video model a call may name, Hypit's own models included, each with its default leg (`chinaapi` or `hypit`), its `legs` key and what a call through the tools can use today (text, first frame, first + last frame, how many reference images, a real person's photo, clip range, output tiers; no price). It serves it as `catalog` in the `image` / `video` blocks of `/tools/v1/check` and in `/media/{image,video}/check`. `plugins/apexnodes_media_catalog.py` reads it: `generate_image`'s `model` parameter no longer lists ids, a model is checked against the catalog before any request (an id it lacks, or one switched off, is refused with the server's reason and the ids that work), and a named model's health is read on its own leg (`hypit:<model>` for a Hypit model) through the one-line change in `apexnodes_gateway._leg_view`. A server without a catalog gets every name through unchecked: it validates the name itself. The pause sentence no longer points at the "+" menu: product mode hides it and the assistant may have picked the model.

Who picks: the composer writes `apex.generation_model_choice` at start-up and whenever the picker visibility changes: `assistant` while `$modelChoiceHidden` hides the generation pickers (tier mode, single-thread product mode on an APEX account), `user` while they are shown (developer mode, a user's own key). With `assistant`, the saved `generation_image_model` is the hidden default, not a choice, so the assistant's `model` stands (or none: the platform default). With `user`, or with no key at all (an older renderer), the saved choice wins as in hc-845. `APEX_PRODUCT_DEFAULTS` still seeds both model keys; nothing else changed in the seed.

Outlets: renderer start-up effect (`context-menu.tsx`) and `saveGenerationModelChoice` (`generation-models.ts`); the image and video plugins' `_desktop_*_model` and handlers; the shared gateway leg lookup and pause copy. `generate_video` takes the same change on top of hc-1136: its `model` lists no ids (plugin contract v16, with two behaviors both contract tests run on both legs: `model_checked_against_served_catalog`, `hidden_picker_lets_the_assistant_pick`). This is the fix for the hidden picker's saved Seedance 2.0 Mini replacing the assistant's video model in product mode. An installed Desktop keeps its old plugin until it updates.
