# WP4 输入框：粘贴即识别 + 只留附件、语音、发送（QA 报告）

票号：hc-994（Kael 批准，经短视频评测主会话转达；放进 0.17.61）。分支 `claude/hc-994-paste-actions-composer`，基于 fork main `922a8e3591`。

截图来自临时 dev harness（真实组件、示例数据、Electron 桥接打桩），不是打包产物；harness 页面没有提交。

## 1. 用户看到什么

### 粘贴即识别

- 在聊天输入框或首页输入框里粘贴抖音、小红书、视频号、快手、哔哩哔哩的链接（包括 App 复制出来的整段分享文案、短链、没写 `https://` 的手打链接），输入框上方出现三个胶囊：「转逐字稿」「拆它为什么火」「仿写成我的脚本」。
- 拖进本地视频（MP4、MOV、M4V、WebM、MKV、AVI、FLV，和桌面端视频分析认的格式一致），或用「+ › 添加文件或视频」选进来，同样出现这三个胶囊。
- 点一个胶囊就发出一句预设请求，例如「把这条抖音视频转成逐字稿：https://v.douyin.com/iRNBho6u/」。分享文案里「复制打开抖音…」这类 App 自带的话不带进去；用户在粘贴之外自己打的字另起一行跟在后面，不会丢。
- 不想用就照常打字发送。胶囊跟着链接走：链接还在输入框里就一直在，发出去或删掉链接就消失，没有关闭按钮（和旁边的建议胶囊一样）。
- 请求只用现有工具和技能：`social_download` / `media_transcribe`、`video-script-breakdown`、`douyin-video-transcript`。不新增任何后端接口。

### 输入框只留附件、语音、发送

| 位置 | 之前 | 现在（平时） | 开发者模式 |
|---|---|---|---|
| 聊天输入框左侧 | 「+」能力菜单、✦ 场景、审批 | 只有「+」 | 和之前一样 |
| 聊天输入框右侧 | （自带密钥时的模型胶囊）、⚙ 语音设置、开始语音对话、发送 | 开始语音对话、发送；麦克风正在听写或语音唤醒在听时，多一个显示该状态的语音按钮 | 和之前一样 |
| 首页输入框底栏 | 附件「+」、选择工作流、（模型）、语音、发送 | 「+」、语音、发送 | 选择工作流留在底栏 |

「+」菜单：

- 添加图片 / 添加文件或视频 / 添加文件夹（hc-572 后续轮拿掉过，这次按 WP4 的「附件」加回来，因为第一次用的创作者不知道可以拖）。
- 生成：图片、视频（原样）。
- 高级 ›：场景…（打开原来那个可搜索的场景单）、审批方式 ›（手动审批 / 智能审批 / 完全访问，三档原样）、语音设置 ›（开始语音对话、语音听写、朗读回复、APEX 语音唤醒）、已启用技能、未启用技能、连接器、插件条目、「@ 引用文件」提示。
- 首页输入框的「+ › 高级」里是「选择工作流」（选了模板时显示「工作流：模板名」）。

选模型：hc-960 的规则不变。三档模式（APEX 账号 + 开关打开）下任何地方都没有选模型；「高级」里也不放。开关没开或自带密钥时，模型胶囊照旧在输入框行里，不进「高级」。

开发者模式（设置 › 外观 › 开发者模式，默认关）：输入框保持改版前的整排按钮，「+」菜单是平铺的老样子（多了附件三行）。理由：做这些控件的人和想一键直达的人还用得上；平时模式不受影响；两种都有测试钉住。

### 顺手修的现成问题：聚焦粘贴的链接不变引用（待 Kael 审的行为变化）

`resolveExactLinkPaste` 用全局正则 `URL_RE.exec` 判断「是不是只粘了一个链接」，之后 `lastIndex` 停在那个链接后面；同一次粘贴紧接着的 `linkifyUrls` 用 `matchAll` 从这个位置往后扫，于是聚焦粘贴时第一个链接从不变成 `@url:` 引用，而且这个状态是全局的，上一次粘贴会影响下一次。没聚焦时 ⌘V、手打链接按空格都会变引用，三条路不一致。

本 PR 在 `linkifyUrls` 开头把 `lastIndex` 归零。结果：普通链接聚焦粘贴后会稳定变成 `@url:` 引用（发送前网关会抓取网页，这本来就是这条路的设计，⌘V 和手打一直如此）；短视频链接不受影响，仍是纯文本。如果 Kael 更想让普通链接也保持纯文本，那是另一个产品决定，可以单独改，不影响本 PR 的胶囊。
