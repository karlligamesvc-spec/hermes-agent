# hc-973 — 过程区说人话：一句状态、人话步骤、数据从哪来

## 范围

- 2026-10-19 Kael 认可的原型（画布「过程区 · 说人话」画板），原话：「默认一句状态，点开是人话步骤和"数据从哪来"，推理收起成"想了 N 秒"，工具名和耗时只在开发者模式显示，失败给三个按钮。」
- 起因：10-18 真机评测里过程区满屏「Thought for 2s」「Tool Search 2 results 9ms」「Used 4 tools」、技能 slug 和接口参数名；hc-953（#421）已补齐中文，这是第二步。
- 只改 Desktop 渲染层（`apps/desktop`）。后端、插件、飞书侧没动。

## 改后的样子

| 状态 | 过程区 |
|---|---|
| 进行中 | 一行：当前这一步的进行时 + 「第 N 步」，如「正在识别语音… 第 2 步」。慢的步骤下面加一句「这一步要久一点，你可以先去忙别的。」 |
| 完成 | 一行：「下载视频 → 识别语音 → 看关键词热度 → 搜同类作品 · 用时 2 分 10 秒 · 看步骤」 |
| 看步骤 | 每步一行：标题 + 结果（「下载了 1 个视频，1 分 43 秒，12.6 万赞」），每步一个「数据从哪来」，点开是来源一句话 + 链接 + 搜索词 + 条数；委派的子任务单独一组；最后一行「用到的方法：视频脚本拆解、事实核验」 |
| 推理 | 整轮只有一个「想了 15 秒 ›」，点开才看全部推理；不再在正文里滚动 |
| 失败 | 「识别语音没成功 · 第 2 步，共 2 步」，步骤自动展开，下面红框：原因（工具原话里有代码名或英文时换成「这一步没有拿到结果。」）+「已经拿到的部分不会丢。」+ 三个按钮「重试」「换个办法」「先给我能出的部分」 |
| 开发者模式 | 设置 → 外观 →「开发者模式 关/开」，默认关。打开后步骤默认展开，每步多一行「技术细节 · 工具代码名 · 耗时 · N 次调用」，下面是每次调用原来的那一行（原始参数和输出、命令和输出、搜索结果） |

### 实现要点

- 一轮 = 两条用户消息之间所有助手气泡。live 时一轮拆成好几个气泡（每次中途说明封一个），从历史加载时是一个气泡，所以只按整轮的部件顺序算，不依赖气泡边界。
- 过程块挂在这一轮**最后一段**工具活动的位置：进行中时跟着最新的动作走，完成后正好在答案上面。其余几段工具活动不再单独渲染，都算进这一个块。
- 连续调用同一个工具算一步（并行搜索 2 次 = 「搜同类作品 · 找到 40 条作品」）。`tool_search`、`tool_describe`、`skill_view`、`skills_list` 是准备，不算步骤；开发者模式下挂在它准备的那一步的技术细节里。
- 编辑文件、生成图片、委派任务既是步骤，卡片也照旧留在原位；提问卡、连接授权卡、生成阶梯卡、给其他助手发消息的通知只留卡片，不算步骤。
- 工具中文名表（hc-953）之上，新表 `i18n/*-process.ts` 给 113 个工具各配：进行时（running）、标题（title）、完成摘要模板（done）、可选的来源一句话（source）。没登记的工具一律「正在处理… / 处理 / 好了」。
- 新文案挂在 `assistant.tool.process` 下，类型在 `types-process.ts`；`en.ts / zh.ts / zh-hant.ts / ja.ts / types.ts` 只改了设置项的 7 行文案，行数不变（FILE_LINES 棘轮）。

### 和原型不一样的地方（请 Kael 看）

1. **进行中只写「第 N 步」，不写「共 M 步」**。助手事先不报计划，总数只有做完才知道；完成和失败时写「共 M 步」。
2. **没有「大约还要 1 分钟」**。没有可信的估计；慢步骤（转写、视频生成、批量、直播录制）换成「这一步要久一点，你可以先去忙别的。」，不承诺「做完提醒你」。
3. **「拆结构」「写脚本」不是步骤**。它们是模型自己想和写，不是工具调用；链条里只出现真做过的事，写的结果就是答案本身。
4. **模型的中途说明照旧显示在原位**（如「好的，我先把视频下载下来转成文字…」）。这是助手自己的话，藏起来有把真正答案一起藏掉的风险；说明里出现工程词要靠提示词收（后续 3）。
5. **失败按钮用通用文案**。原型里「换个办法：先用视频自带字幕」这种具体建议要模型给，列为后续。
6. **开发者模式复用现有开关**：原来的「工具调用显示 产品/技术」改名「开发者模式 关/开」，默认关，存储键不变（已经选了技术的人升级后直接是开）。「默认折叠推理过程」改成只在开发者模式下生效。

## 出口清单

工具调用和推理所有能上屏的地方，逐个查过：

| 出口 | 处理 |
|---|---|
| 消息里的工具组（assistant-ui `ToolGroup`） | `process/tool-group-slot.tsx` 取代旧的 `ToolGroupSlot`：卡片原位，活动并入整轮的过程块 |
| 旧的「Explored 3 files」摘要行和单行滚动条（`ToolRun`、`ToolRunHeader`、ticker） | 删除 |
| 每次调用的行（`ToolEntry`） | 只在开发者模式的「技术细节」里出现；改为同时显示可读输出（命令、退出码、stdout/stderr、搜索结果）和原始参数/结果。原来技术模式会把可读输出藏掉，现在行只在技术模式出现，再藏就永远看不到了 |
| 推理组（`ReasoningGroup` / `ThinkingDisclosure`） | 有工具活动的一轮：并进过程块的「想了 N 秒」；没有工具的一轮：同样的收起小签，开发者模式外不再有正文里滚动的预览 |
| 线程尾部状态行（模型正在写工具调用时的提示） | `toolPresentVerb` 改用步骤的进行时，起草时就说「正在下载视频」，和之后的过程行同一句话 |
| 审批条（`PendingToolApproval`） | 终端/代码调用等审批时，审批条挂在过程行下面（原来挂在被折叠的行下）；改文件的审批仍在原位卡片上 |
| 委派卡（`DelegateTool`） | 原位不变；步骤里多一组「子任务」，列每个目标和状态 |
| 提问卡、连接/MCP 授权卡、生成阶梯卡、图片生成卡、改文件的 diff | 原位不变 |

| 待办面板（输入框上方状态栏） | 不变（本来就不在对话里） |
| 本轮改动文件卡、错误卡（`ErrorPrimitive`）、回合时长「⏱ 2:10」 | 不变 |
| 时间戳设置（`display.timestamps`） | 过程行显示整轮工具起止时间，推理签显示推理起止时间，和原来的行、思考头一致 |
| 设置 → 外观 → 工具调用显示 / 默认折叠推理过程；设置搜索 | 改名「开发者模式」，说明改写；搜索跟着用新文案 |

| Bot 房间（hermes-bots 插件） | 查过，不渲染工具调用，无需改 |
| 渲染预算 `lib/render-weight.ts` | 查过，仍按旧的行估价，现在实际挂载更少，只会更早出现「显示更早」。只影响性能，未改 |
| `short-session-hang-repro` 调试页 | 只报告已绘制的工具行数，不卡流程，未改 |
| **飞书后台任务进度消息**（apex-nodes `app/services/feishu_background_delivery.py`） | **未改，后续**：应该用同一套人话标题 |
