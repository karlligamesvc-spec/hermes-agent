# hc-1113 快速输入：默认值、小窗的名字、送不到时要说

来源：hc-1083 M7 多助手验收的问题 11 / N1（0.17.67 正式包）：

1. 全新安装时快速输入是关的，和 `sanitizeQuickEntrySettings` 注释写的「Default ON」对不上；
2. 多助手开着时，小窗写「问 剪辑助手 点什么…」，主窗口切到 APEX 以后小窗还是这个名字；
3. 小窗里提交的一句话哪个助手都没收到，desktop.log 也没有一行。

## 1. 默认开还是关

- 上游（aa3121bb，2026-07-26）是开：读不到 quick-entry.json 就按默认开。
- APEX 在 hc-684 合并 Hermes v0.20（c5e773aa，2026-08-07）时，把读不到文件改成按关。那时快速输入是新进来的上游功能。
- hc-1001（2026-10-20）的 QA 记录写着「默认关……这一票不改」。
- 所以 APEX 的原意是关。这次没有改成开：`QUICK_ENTRY_DEFAULT_ENABLED = false` 放在 `electron/quick-entry.ts`，主进程读文件和 `sanitizeQuickEntrySettings` 都用它，注释也改成一致。
- 唯一的行为变化：文件存在但没有 `enabled`（或不是 true/false）时，以前按开，现在和没文件一样按关。

两种做法的影响（要 Kael 定）：

| 做法 | 影响 |
|---|---|
| 保持关（本 PR） | 新装和所有没碰过这个设置的用户都是关的。产品模式下「设置 › 高级」被 hc-1109 收起来了，用户看不到开关，只能切到开发者模式才能打开。 |
| 改成开（只改这一个常量） | 所有没有 quick-entry.json 的安装（包括升级上来的老用户）下次启动就会全局占用 ⌘⇧Space。被别的应用占用时只记日志、在「高级」里提示；产品模式下用户看不到，也关不掉。 |

## 2. 改了什么

- **名字跟着前台助手**：主窗口推给小窗的状态里带上当前助手（只在多助手开着时带，单助手时推的内容和以前逐字节一样）。主进程留着最新一份，每次按快捷键唤出小窗时一起交过去（`shown`），新开的小窗加载完也会拿到。localStorage 只管第一帧。
- **送到小窗写的那个助手**：提交的一句话带着小窗当时写的助手。主窗口那边如果已经换了助手，先切过去，等它的对话就绪再发；30 秒没就绪就算送不到，不会落进别的助手的对话。原来的等待在超时后会再等一轮，一直等下去，现在不会了。
- **送不到要说**：主进程给每句话一个编号，主窗口先回「收到」，再回「送到了 / 没送到 + 原因」。每句话在 desktop.log 里有且只有一行（不含原文）。没送到的话回到小窗输入框里，下面一行红字说原因，按回车可以再发。主窗口 5 秒不回「收到」、60 秒不回结果，也算没送到。
- 原因：助手还在回上一条（busy）、没能打开那个助手（switch）、主窗口关着（no-window）、其他（主窗口没接、出错、被拒）。

## 3. 验收（dev Electron，全新空环境，本机 mock 模型）

- 本分支 `npm run build` 的产物，`HERMES_HOME` 和 userData 都是新建的空目录，`APEXNODES_SINGLE_THREAD=1`；多助手用 `APEXNODES_MULTI_BOT=1`，单助手用 `=0`。点「使用自己的密钥」进去，模型是本机 mock，不发付费请求。
- 第二个助手「剪辑助手」是在界面上点「+」建的，三个首问也在界面上答完。
- 全局快捷键：脚本发不出系统级按键，所以快速输入由主进程自己的 `toggleQuickEntryWindow` 唤出（只在本地构建里临时挂出来，没提交）。唤出之后的显示、隐藏、提交、IPC、主窗口路由都是真实代码。
