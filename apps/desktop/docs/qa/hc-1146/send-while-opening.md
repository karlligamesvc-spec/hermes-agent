# hc-1146 后续：对话还没接上时发的消息先排着，启动时预热上次用的助手

0.17.72 发布后，用户反馈：「安装更新启动 Apex 程序后打开会话，发消息半天没有反应。」本页是这个修复的 QA 记录；改动、出口清单和反向验证见 PR。

## 截图

截图来自 dev Electron + 真引擎 + 假模型（e2e mock），不是打包产物。场景是冷切换：点「选题助手」时，它的引擎没有在跑；点完马上打字、回车。

| 文件 | 内容 |
|---|---|
| `screenshots/send-before-cold-switch.jpg` | main `3992e465`：回车后文字还留在输入框里，只弹一个一闪而过的「正在打开对话，稍等一下再发。」 |
| `screenshots/send-after-cold-switch-held.jpg` | 本分支，回车后 0.7 s：消息立刻成为输入框上方变淡的气泡，下面写「选题助手 接上后发送 · 取消发送」；输入框上方常驻一行「正在唤醒 选题助手…现在发的消息会先排着，接上就发。」 |
| `screenshots/send-after-cold-switch-sent.jpg` | 本分支，接上后：只发出一次，收到回复 |

## 计时

3 次取中位数；测量脚本和原始数据在协调会话的共享笔记 `held-sends-evidence/` 里。

| 场景 | main | 本分支 |
|---|---|---|
| 打开 APEX 后马上给 APEX 发一句：从启动到被接受 / 到送达模型 | 9.8 s（按 3 次）/ 12.5 s | 6.2 s（第 1 次）/ 8.6 s |
| 接着点上次用的剪辑助手发一句：从点击到被接受 / 到送达模型 | 6.1 s（按 9 次）/ 8.1 s | 0.18 s / 3.0 s |
| 冷切换到选题助手：从点击到被接受 / 到送达模型 | 30.7 s（按 50 次）/ 31.6 s | 0.19 s / 31.6 s |

冷切换这一行，送达时间两边都是约 31.6 s，本 PR 没有改变。原因是另一个问题，hc-1146 另有 PR 处理：切换时恢复会话要逐个问各个 profile，路上某个没在跑的助手要等 30 s 的后台 slot。

## 预热

重启后什么都不点，等 20 s，看在跑的引擎：

- main：只有 `default`。
- 本分支：5 s 时已经是 `default, apex-bot-2`（上次用的剪辑助手），屏幕仍停在 APEX。
